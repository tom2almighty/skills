# 国际化（i18n）

## 目录
- 何时启用

- 表单校验信息
- 日期、数字、金额

## 何时启用

- 仓库已有 i18n，或用户明确要求多语言：**硬约束**，组件内不得硬编码未翻译的业务文案。
- 新项目：默认启用 `zh-CN` + `en-US`。
- 原型、内部工具、一次性页面且用户未提多语言：先不搭建，文案集中放在页面顶部常量中，便于日后迁移；不确定时简短询问。

## 配置要点

- Vite SPA：`i18next` + `react-i18next` + `i18next-browser-languagedetector`；SSR/Next.js：`next-intl`。
- 不写死 `lng`，检测顺序为 `localStorage` → 浏览器语言；`fallbackLng: 'en-US'`。
- 语言包放 `@/locales/zh-CN.json` 与 `@/locales/en-US.json`，两份 key 保持一致。
- 在 `src/types/i18n.d.ts` 中基于 `zh-CN.json` 推断 key 类型，让缺失或拼错的 key 在编译期报错。

## 表单校验信息

zod 的错误文案同样要走翻译，这是最容易漏的地方。两种做法任选其一：

- 在 schema 工厂函数里注入 `t`：`const schema = (t: TFunction) => z.object({ name: z.string().min(1, t('form.required')) })`，组件内用 `useMemo(() => schema(t), [t])`。
- 或配置 zod 的全局 error map，按当前语言返回消息。

语言切换后，已显示的错误信息应随之更新。

## 日期、数字、金额

用 `Intl.DateTimeFormat` / `Intl.NumberFormat` / `Intl.RelativeTimeFormat`，locale 取当前 i18n 语言，不手写格式化字符串。表格里的数字列配合 `tabular-nums`。
